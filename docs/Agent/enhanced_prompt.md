【自我审查清单】
每个细分任务完成后、跑测试前，逐项自查，不通过的项必须修复后才能跑测试：
1. 错误处理：所有外部调用（DB/Redis/HTTP/LLM/akshare）是否有 try/except？异常是否被吞掉（except: pass）？
2. 空值处理：None/空列表/空字符串是否处理？是否会触发 AttributeError/KeyError/IndexError？
3. 类型一致性：函数返回类型是否与 schema/model 定义一致？Optional 字段是否正确？Pydantic 校验是否通过？
4. 资源泄漏：文件/连接/锁是否正确关闭？with 语句是否使用？Redis 连接是否归还连接池？
5. 并发安全：多线程/Celery 场景下是否有竞态条件？缓存击穿锁是否正确使用 SETNX？数据库事务是否正确？
6. 幂等性：重复调用是否产生脏数据？upsert 是否正确使用 on_conflict？定时任务重复触发是否安全？
7. 日志：关键路径是否有 info 日志？异常是否有 error 日志（含 traceback，用 logger.exception）？是否有敏感信息（API Key/token）泄露到日志？
8. 向后兼容：现有 API 的请求/响应格式是否被破坏？旧数据是否可读？数据库迁移是否只加不改？
9. 测试：新增代码是否有对应测试？测试是否覆盖了正常路径+异常路径+边界条件？
10. 代码风格：是否遵循项目现有命名/分层/导入顺序？是否引入了不必要的新依赖？是否有硬编码的魔法数字/字符串？

【测试要求】
- 测试必须覆盖：正常路径、异常路径（外部调用失败时的降级/报错）、边界条件（空值/最大值/并发）。
- 测试不得只用 mock 跳过实际逻辑（外部 API 调用可 mock，但 DB/缓存逻辑必须真实执行）。
- 每个测试函数必须有明确的断言，不得只有"不抛异常就算通过"。
- 跑测试时必须显示通过数/失败数，失败的测试必须修复或明确说明原因并获得同意。
- 全库 pytest 通过率必须 100%，不得有 skip 或 xfail（除非明确同意）。
- 新增测试放在 tests/ 目录下对应模块文件中，命名遵循现有模式。
