# V0.2 开发顺序参考指南

> 本文件记录 V0.2 版本的拓扑依赖关系和4波开发顺序。
> 每次编写开发提示词前必须重新阅读本文件，确保提示词中的任务顺序符合拓扑关系。
> 本文件只记录开发顺序和依赖关系，不记录具体技术实现细节。

---

## 一、后端内部依赖关系（必须严格按顺序）

```
阶段四(DataProvider) → 阶段一(缓存体系) → 阶段二(WS推送)
   （数据源底层）        （缓存数据来自Provider）  （WS推送数据来自缓存）

阶段五(AI流式稳定性) → 阶段六(记忆系统) → 阶段八(长会话+策略生成)
   （SSE基础设施）        （记忆写入反馈需SSE事件）  （摘要需记忆存储+SSE）

阶段七(多智能体) 相对独立（LangGraph新架构，但SSE推送复用阶段五框架）
阶段三(标的目录) 相对独立（可与阶段一并行）
```

---

## 二、前后端对应依赖（前端强依赖后端接口）

```
前端阶段一(加载体验)   ← 后端阶段一+三(sync-status接口、搜索新字段)
前端阶段二(WS推送)     ← 后端阶段二(WS服务端)
前端阶段三(搜索关注)   ← 后端阶段三(目录+关注同步状态)
前端阶段四(AI流式体验) ← 后端阶段五(SSE心跳/错误帧/降级)
前端阶段五(记忆可视化) ← 后端阶段六(记忆管理API)
前端阶段六(多智能体)   ← 后端阶段七(agent_step SSE+运行历史API)
前端阶段七(长会话+策略) ← 后端阶段八(token预算+策略校验+模板+回测)
```

## 三、4波开发顺序（严格按此执行）

### 第一波：行情数据基础（约占总工作量40%）

```
1. 后端阶段四（DataProvider可插拔）    ← 最先做，数据源底层
2. 后端阶段一（缓存体系）              ← 依赖Provider，K线/快照/指标缓存
3. 后端阶段三（标的目录）              ← 与阶段一并行，相对独立
4. 前端阶段一（加载体验）              ← 后端阶段一+三出接口后跟进，不依赖WS
5. 后端阶段二（WS推送）               ← 依赖阶段一缓存
6. 前端阶段二（WS）+ 前端阶段三（搜索关注） ← 跟进联调，前端三依赖前端二的wsStore
```

**第一波前端内部分组：**
- 第一批：前端阶段一（加载体验）—— 只依赖后端阶段一+三，可独立开发，不涉及WS
- 第二批：前端阶段二（WS基础设施）+ 前端阶段三（搜索关注）—— 阶段二是WS基础设施，阶段三的关注列表订阅更新依赖阶段二的wsStore

### 第二波：AI基础加固（约占25%）

```
7. 后端阶段五（AI流式稳定性）          ← SSE心跳/超时/错误帧/降级，相对独立
8. 前端阶段四（AI流式体验）            ← 跟进联调
9. 后端阶段六（记忆系统，int8量化版）   ← 依赖阶段五SSE事件基础设施
10. 前端阶段五（记忆可视化）           ← 跟进联调
```

### 第三波：AI高级功能（约占25%）

```
11. 后端阶段七（多智能体）             ← LangGraph架构+agent_step SSE，较重
12. 前端阶段六（多智能体可视化）       ← 跟进联调
13. 后端阶段八（长会话+策略生成）      ← 依赖阶段五SSE+阶段六记忆存储
14. 前端阶段七（长会话+策略生成体验）  ← 跟进联调
```

### 第四波：全链路联调打磨（约占10%）

```
15. 全链路联调、边界场景、性能优化、部署验证、收尾检查
```

## 四、编写提示词时的注意事项

1. **每波提示词必须明确标注该波在4波中的位置**（如"第一波"），以及该波包含哪些后端/前端阶段。
2. **任务顺序必须严格符合拓扑关系**，不能随意调整。特别是第一波中前端阶段一和前端阶段二+三是分批的。
3. **每个任务必须标注其依赖的前置任务**（如"前端阶段二依赖后端阶段二已完成"）。
4. **前端阶段之间的依赖也要标注**（如"前端阶段三的关注列表订阅更新依赖前端阶段二的wsStore"）。
5. **如果某波的后端已全部完成，前端可以按拓扑顺序连续开发，但仍需在提示词中说明分组和依赖关系。**
6. **本文件是编写提示词的强制参考，每次编写前必须重新阅读。**
