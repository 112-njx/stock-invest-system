# 原始数据一键更新与行业结果缓存

## 页面上的两个入口

1. **一键更新原始数据**：暂停新的本地源读取，停止 `stockdb-local`，运行 Windows `数据更新.exe`，按下载清单校验大小和 SHA-256，生成新的数据版本，启动服务并验证真实 SDK 查询。不会创建备份，也不会自动导入项目数据库。
2. **同步本地行情**：复用现有任务，将证券目录、受支持的固定指数和关注标的行情导入项目数据库，并失效相关显示/指标缓存。不下载原始文件、不调用更新器、不重启服务。

先等已有手动同步结束，再更新原始文件；成功后再同步至项目。更新失败时保留维护状态和错误，本地源不能继续返回旧缓存；项目 PostgreSQL 中的历史仍可查看。确认上次更新器退出后可从页面重试。失败后的更新可能已改变部分文件，不自动回退或自动启动未经验证的数据。

## 本机更新助手

启动开发环境的 `deploy/start_dev.sh` 会启动助手。直接使用 Compose 时先执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File deploy/start_stockdb_update_agent.ps1
```

默认 Python 为 `D:\Pycharm\python\python.exe`、原始数据根为 `D:\Free_stockdb\stockdb`；可用 `-Python`、`-StockdbDirectory` 覆盖。生产编排使用 `-ComposeFile deploy/docker-compose.yml`，不得让开发和生产两套服务同时打开同一数据目录。

助手为隐藏的 Windows Python 进程，使用内核文件锁防止重复运行。管理员 API 只通过 `stock_backend/data/stockdb-control` 共享目录提交固定的 update 任务，不开放任意命令执行端口，也不向后端挂载 Docker socket。原始文件仍绑定挂载 D 盘目录。

页面显示助手心跳、任务阶段、失败原因和数据版本；助手断开时入口禁用。更新器日志为 `stock_backend/data/stockdb-control/updater.log`，助手日志在同目录。助手中断后不会自动重新启动可能仍在被更新的数据目录；重启助手后会等待已有更新器退出，再允许重试。

数据版本是更新成功后生成的 UUID，附带清单/文件校验信息，不以最新交易日作为版本。首次部署只登记当前本地快照，不触发下载；LevelDB 已轮换的旧下载 WAL 不用于首次登记校验。正式更新的 SHA-256 校验在更新器退出、数据库启动之前执行。

请使用新入口更新数据。若绕过助手手动运行更新器，必须先停止容器，更新器退出后再执行一键更新完成校验和版本切换；“同步本地行情”不会替代数据版本切换。

## 完整结果缓存

- 文件：`stock_backend/data/stockdb-cache/industry.sqlite3`，绑定挂载到 `/var/cache/stockdb`，不写入作者的数据目录或镜像。
- 保存官方 SDK 从固定 2000 年基准计算的完整行业结果。只改变请求开始日期时可直接截取，重启桥后仍可复用。
- 键包含行业、周期、qfq、算法版本和数据版本；另区分结束日期，避免将较晚完整周/月数据冒充较早截止时的未完成周期。每个行业/周期只保留一个截止快照，不按请求开始日期重复保存。
- 普通 `/refresh` 只清理短期内存缓存，不删除持久化结果；更新后使用新版本键，写入新结果时清理旧版本。失败、空数据和不合法结果不保存。
- 内存结果缓存最多 32 项、16 MiB；SQLite 页面缓存每连接 4 MiB，禁用 mmap。有效磁盘载荷上限 128 MiB，按最近访问淘汰；SQLite 文件会复用空闲页，文件大小还包含索引、事务和空闲页。
- 磁盘命中不等待其他 SDK 长任务。`/metrics` 的 `disk_hits` 与请求日志 `source=disk` 可区分磁盘复用和真正的 SDK 计算。
- 不引入常驻 SDK，不做按年复用。成功计算后仍同步到项目 PostgreSQL；此缓存用于减少同步、补拉和重试的重复计算，不替代项目历史存储。

## 验证范围

脚本测试覆盖缓存重启、同日期历史修正的版本失效、周/月截止边界、错误不缓存、内存预算、并发磁盘命中、更新器失败、SHA-256 失败和成功停启顺序。更新 API 测试覆盖管理员权限、助手离线、同步互斥、重复提交及重试保护；前端测试覆盖两个入口的文案、互斥和助手离线状态。

自动测试中的更新器与停启操作使用模拟对象和临时小文件，没有触发真实下载、修改原始行情或创建备份。实际源查询、磁盘命中和服务可访问性另在本地验证；首次真实更新仍需观察本机更新器的下载输出和清单校验结果。

本轮验证：脚本测试 20 项、后端相关测试 68 项通过；管理页交互检查、类型检查和生产构建通过。股票、ETF 与行业日/周/月共 11 组、348 条真实记录均与 Windows 基准一致。单个行业的三个完整截止快照有效载荷 1,783,403 字节，SQLite 文件 1,802,240 字节；重启临时桥后日线查询约 0.212 秒，`disk_hits=1`、`sdk_calls=0`，确认没有再次计算。
